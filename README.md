# 贝塞尔根系重建（matlab / 图片+位姿 → 重建图与数据表）

围绕 `plantroot06.m`（三维贝塞尔树状根系，向下生长）实现的**根系三维重建工具集**。既能**从 matlab 文件**、也能**从 24 张图 + 相机位姿**出发，还原出根系模型，并输出**重建图**与**数据表**（空间坐标表 / 贝塞尔定义点表 / 根表）。

提供两种使用方式：

1. **Web 端程序**（推荐）：纯 Python 标准库实现的 Web 服务，三个输入模块，浏览器点选文件即可出结果。
2. **命令行脚本**：直接跑 Python 脚本。

数据表明细：节点图结构，每条根的起点/终点都锚定在**分支点/末端点节点**上；曲线由一组贝塞尔定义点（端点 + 控制点）确定。

---

## 一、Web 端程序（开箱即用）

零依赖（仅使用 Python 标准库 `http.server`，无需 Flask），三个输入模块：

| 模块 | 输入 | 输出 |
|---|---|---|
| **模块①** matlab → 24 图 + 位姿 | `plantroot06.m` | 24 张**带颜色标记**的曲线图（15°/张）+ 相机位姿文件 `pose.json`（含标记约定 `mark_meta`） |
| **模块②** matlab → 模型根表 | `plantroot06.m` | 根表 `root_table.csv/.sql` + 重建图 |
| **模块③** 24 图 + 位姿 → 重建 | 24 张**带颜色标记**的图 + `pose.json`（可选） | 空间坐标表 `reconstructed_points.csv` + 贝塞尔定义点表 `control_points.csv` + **重建根表 `root_table.csv/.sql`（14 列，含拓扑）** + 重建图 + 对比图 |

### 启动

```powershell
python web_server.py
```

浏览器访问 `http://127.0.0.1:8090/`。

> Windows 下如中文乱码，先执行 `chcp 65001` 并设 `$env:PYTHONIOENCODING='utf-8'`。

### 接口（后端）

| 方法/路径 | 作用 |
|---|---|
| `POST /api/from_matlab` | 模块②：matlab → 模型 + 根表 + 重建图 |
| `POST /api/from_images` | 模块③：24 图(+pose) → 空间表 + 贝塞尔图 + 对比图 |
| `POST /api/gen_views` | 模块①：matlab → 24 图 + 位姿文件 |
| `GET /results/<path>` | 下载生成的图/表 |
| `GET /api/zip_views/<job>` | 把某任务的 24 图 + pose 打包成 ZIP 下载 |

入口③只消费上传图与位姿：检测直接在**上传图像素**上做（管线内无自渲染旁路），因此重建结果随上传的视图集变化。标记约定由模块①写入 `pose.json` 的 `mark_meta`（每曲线点数/曲线数/层级），模块③据此解码颜色 → 点的对应关系。

## 四、数据表

### ① 空间坐标表 `reconstructed_points.csv`（三角化出的曲线上点）

```
点序号 | 曲线id | 段内序号 | 类别 | x | y | z
```
`类别` = 起点 / 中间点 / 终点。每条曲线 12 个点，共 120 点。

### ② 贝塞尔定义点表 `control_points.csv`（每条曲线的端点 + 控制点）

```
曲线id | 控制点序号 | 类别 | x | y | z
```
每条曲线反解出一组贝塞尔控制点（5 次 = 6 个：2 端点 + 4 控制点）。

### ③ 根表 `root_table.csv`（模型 → 表，节点行 + 曲线行）

```
序号 | 级别 | 编号1 | 编号2 | 编号3 | 编号4 | 类别 | x | y | z | 粗细 | 成熟度 | 上节点 | 下节点
```
- `级别`：根分支层级（1=主根 …）
- `编号1`：所属曲线/分支段 ID；`编号2`：点在曲线内序号
- `类别`：`节点/分支点/末端点/首节点/控制点1/控制点2/末节点/采样点`
- `上节点/下节点`：起点/终点所连接的分叉节点（对应 Node 结构）
- `粗细`：半径（沿曲线渐变）；`成熟度`：归一化成熟度

## 五、核心流程（图 → 表 → 贝塞尔重建）

1. **标记约定**：每条根取 12 个曲线上点（起点/中间/终点），每点一个唯一颜色（贪心最远点选色），目标点序 `ti = 曲线id×12 + 段内序号`。
2. **渲染**（模块①/CLI）：曲线 + 彩色标记，标记间互斥（重叠簇内按视角轮转只有一个被完整画出，避免新月残片拉偏质心）。
3. **检测**（模块③/CLI）：只读上传图，按最近调色板色 + 连通域取最大块定位 2D 质心与像素半径（不降采样，避免小标记被稀释）。
4. **三角化**：多视角 DLT + 迭代视角剔除（残差 >1.2px 的视角被剔除，含 cheirality 正深度校验）。
5. **空间坐标表**：反求每点 3D 坐标 → `reconstructed_points.csv`（同时保存逐点检测/残差 `detections.json` 供评估）。
6. **贝塞尔反解**：按曲线分组，用**生成参数化 t=k/11**（与标记采样约定一致）最小二乘反解 5 次贝塞尔控制点 → `control_points.csv`。
7. **粗细**：由标记盘像素半径反演 `r = px·Z/(fx·k)`，取各视角中位数（不读模型真值、不加硬编码 taper）。
8. **拓扑与根表**：由"每条侧根起点落在父曲线上"的几何关系重建 主根→分支点→侧根 树，输出 14 列 `root_table.csv/.sql`。

## 六、精度

评估方法：`python evaluate_reconstruction.py`，重建产物与真值逐点对比后自动输出 JSON + markdown 表 + 逐条 pass/fail（完成标准见 `docs/重建优化-prompt与完成标准.md`）。真值来源：seed=0 用 `dense_meta.json` 的 `coord_true`（与 `RootModel(seed=0)` 逐点核对一致）；其它 seed 由 `RootModel(RootParams(), seed)` 直接生成。世界尺度为主根长度 12。

以下为实测数字（`evaluation/eval_*.md` 为各次评估的完整报告）：

| 场景 | 中位 3D 误差 | 最大 3D 误差 | 重投影残差(中位/最大) | 曲线最大偏差 | 主根起点≈原点 |
|---|---|---|---|---|---|
| CLI（修复前基线） | 0.0135 | 0.1222 | — | 0.559 | 0.005（但端点最大 0.108） |
| Web 模块③（修复前基线） | 0.4341 | 5.9055 | — | 5.737 | 5.906（崩坏） |
| CLI（修复后, seed=0） | 0.0014 | 0.0051 | 0.12 / 0.85px | 0.139 | 0.005 |
| Web 模块③ HTTP 上传（修复后, seed=0） | 0.0014 | 0.0051 | 0.12 / 0.85px | 0.139 | 0.005 |
| seed=1 / seed=2 回归 | 0.0016 / 0.0015 | 0.013 / 0.006 | ≤0.12 / ≤1.0px | ≤0.125 | 0.005 |

拓扑与根表：10 条曲线（主根 1 + 一级侧根 3 + 二级侧根 6）全部入库；8 个分支点位置误差 ≤0.004；`上节点/下节点` 构成可从"原点"遍历的有效树；SQL 经 sqlite3 实际导入验证。粗细全部由图像反演：主根起点半径相对误差约 13%（阈值 30%）。

模型→表→拆控制点还原（`make_table.py`，非重建链路）的最大偏差仍为 0.0001。

## 八、限制与说明

- **入口③的输入是带颜色标记的视图集**（模块①生成，或 CLI 的 `views_pts4/`、`data/plantroot_views (1)/`）。颜色标记是本系统做跨视角对应的机制：若输入是无标记的真实照片，需另做特征检测/匹配（不在本项目范围内）。
- **标记渲染互斥**：分叉节点处多个标记投影重叠，管线让重叠簇内各标记按视角轮流被完整画出（其余整视角缺席、不留残片），保证每个被检测的标记质心无偏；被跳过的视角由其余视角补足三角化。
- **粗细反演的截断**：生成端标记有 `MIN_MARKER_R=3px` 下限，投影半径小于 3px 的细根标记会被放大，导致其反演半径偏大（主根起点附近 r≈4.8px 不受截断影响，相对误差约 13%）；细根段粗细仅作渐变参考。
- **评估与回归**：`python evaluate_reconstruction.py` 可对任意重建产物评分；`python run_seed_regression.py --seeds 1,2` 一条命令完成"换 seed 生成视图 → 重建 → 评估"，防止对 seed=0 过拟合。
